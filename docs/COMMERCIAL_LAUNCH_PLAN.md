# خطة إطلاق بُعد تجاريًا

23 أكتوبر 2026. خط الأساس المنشور `9333f54e4c5f1ab6d536583e8abd1a97eb96e21a`. هذه خطة تنفيذ وشروط قبول، وليست إعلان جاهزية تجارية أو اعتمادًا قانونيًا. لا تُفتح مرحلة بدليل اختبار محلي بدل إثبات التكامل المطلوب.

## 1. اعتماد العرض والمحتوى

المطلوب: اسم الجهة المشغّلة وقناة الدعم، السعر والعملة والضريبة، مرات التشغيل، الاسترجاع والنزاعات، معنى الأربع ساعات أثناء الانقطاع، وجدول الاحتفاظ، واعتماد محتوى سؤال وشرط. أُعدت نماذج السياسات وقاموس البيانات والتهيئة من الخادم. تبقى القيم والاعتمادات قرارًا تجاريًا؛ لا يُفترض سعر أو التزام دعم.

شرط الإغلاق: منتج ومحتوى معتمدان، ومعلومات منشأة وسياسات تطابق السلوك الفعلي.

## 2. عزل الإنتاج وإعداد الأسرار

أُنجزت قاعدة تطوير خاصة ونموذج إعداد صريح وحدود طلبات موزعة. جرد Vercel لا يحتوي متغيرات تشغيل. المطلوب: هدف إنتاج مستقل معتمد، مناطق استضافة مناسبة، سجل ترقيات متطابق، وأسرار خادم في لوحات الاستضافة. لا تُنسخ الأسرار إلى المحادثة أو التوثيق.

شرط الإغلاق: قراءة إعدادات البيئة الصحيحة دون كشف القيم، وترقية/رجوع متوافقان، وعدم تسرب مفاتيح التجربة إلى الإنتاج. لا تُنشأ موارد مدفوعة ولا يُعاد توصيف مشروع التطوير كإنتاج دون قرار واضح.

## 3. ربط Discord واختباره فعليًا

أُنجز PKCE والجلسة المشفرة والتحقق من هوية الهوست والتجديد والخروج والحماية قبل طلبات المزود. المتبقي الخارجي: إعداد تطبيق Discord وسرّه وcallback/allowlist في Supabase، ثم إعدادات الاستضافة الخاصة.

شرط الإغلاق: دخول فعلي، رفض callback مزوّر، انتهاء/تجديد/خروج وانقطاع، تبويبان وحسابان معزولان، وأدلة على النسخة المختبرة. المزود الوهمي لا يغلق هذا الشرط.

## 4. شراء Whop التجريبي وتسليم الرصيد

أُنجز في هذه الدفعة: طلب خادم قابل لإعادة المحاولة، فحص خطة المزود، رابط Sandbox مرتبط بالطلب، توقيع HMAC للـbody الخام والوقت والجهة والإصدار، وإعادة قراءة الدفع ومطابقة المبلغ/العملة/الخطة/الطلب قبل منح مرة تشغيل واحدة. مسارا `/api/checkout` و`/api/sandbox-webhook` يحتاجان أعلام ومفاتيح Sandbox؛ لا يقبلان مضيف مزود إنتاجي. مسار webhook القديم يبقى غير مفعل.

أُنجز اختبار API→SQL→توقيع اختباري→رصيد، وإعادة الإشعار دون زيادة ثانية. لا يمثّل ذلك عملية Whop حقيقية. المطلوب: حساب Sandbox وخطة/ضريبة معتمدتان، تسجيل webhook بإصداره، واختبار نجاح/رفض/تكرار/تأخير ومبلغ خاطئ من المزود الحقيقي. المتبقي هندسيًا قبل الإنتاج: طابور دائم وتسوية وقرارات الاسترجاع/النزاعات وإثبات idempotency المزود. لا يوجد مسار دفع إنتاجي مفعّل.

## 5. الأمان والخصوصية

أُنجز عداد طلبات ذري، HMAC بدل IP الخام، 429 مع Retry-After، رفض غياب المحدد أو مصدر عنوان موثوق، وخروج محلي حتى عند تعطل المحدد. أُضيف CSP ومنع التأطير وnosniff وسياسات الموارد/الصلاحيات، وتثبيت GitHub Actions على SHA محدد. أُعد قاموس البيانات، بما فيه نسخ الأسماء داخل إيصالات الحالة.

شرط الإغلاق: مراجعة أمنية شاملة، حماية main وصلاحيات الإدارة، إثبات WAF/إعدادات المزود، وسياسة احتفاظ وحذف تشمل الإيصالات والنسخ وقناة طلبات خصوصية حقيقية. لا تُنشر المسودات كسياسات معتمدة.

## 6. النسخ الاحتياطي والمراقبة والتشغيل

أُنجز دليل تشغيل واسترجاع واستعادة dump محلي معزول وفحص عام متكرر. المتبقي: نسخ بعيدة واحتفاظ/RPO/RTO فعلية، استعادة إلى بيئة منفصلة، قناة تنبيه يصلها اختبار فعلي، مراقبة تأخر webhook/فشل الدفع/انحراف الرصيد، ومشغّل بديل للحوادث.

شرط الإغلاق: استعادة بعيدة وتنبيه مستلم وتمرين رجوع لا يفقد البيانات. وجود Runbook أو قدرة عامة للمزود وحدهما لا يكفيان.

## 7. رحلة كاملة وضغط وتجربة مقدم

المسار: دخول → شراء تجريبي → إشعار موثوق → رصيد واحد → بدء وخصم مرة → انقطاع واستئناف دون خصم → فائزون مكررون وجوائز يدوية → ختام وسجل وملخص مطابق.

أُنجزت اختبارات منطق وSQL ومتصفح وحالات فقد الرد والتعارض والتكامل المحلي. المتبقي: مزودان فعليان، اتصالات PostgreSQL متوازية، حمل متفق عليه وتجربة مقدم حقيقية. شرط الإغلاق تقرير قبول عربي/إنجليزي وجوال/دسكتوب ومنع خصم/تسليم مكرر عبر اتصالين فعليين.

## 8. قرار فتح البيع والتفعيل التدريجي

أداة `launch:check` تتحقق من 16 بوابة إثبات ونوعها وبيئتها وSHA وتاريخها. لا تقبل اختبارًا محليًا بدل إثبات مزود/استعادة/تزامن بعيد. إنها تتحقق من بنية إقرارات الإثبات، ولا تصادق آليًا على صحة محتواها. يسجل CI الهندسي النواقص؛ نجاحه لا يعني فتح البيع. مثال الجاهزية يبقى pending.

المطلوب: مراجعة أدلة مستقلة، قبول تجاري صريح على نسخة مختبرة، دفع إنتاج منفصل، سياسة استرجاع ومراقبة أول تشغيل وشراء فعلي ضمن إطلاق متدرج. لا تُغلق مرحلة رسمية قبل تحقق شروطها التفصيلية.

## ما يحتاج المالك لاحقًا فقط

1. معلومات المنشأة والدعم والسعر/الضريبة وسياسات الاسترجاع والجلسة والاحتفاظ واعتماد المحتوى.
2. إعداد حسابي Discord وWhop والأسرار في لوحاتهما، أو صلاحيات إدارية مناسبة للإعداد. لا تُرسل الأسرار هنا.
3. اختيار موارد الإنتاج/النسخ/التنبيه حين توجد تكلفة أو التزام، وتسمية مسؤول تشغيل.
4. قبول تجربة فعلية وقرار فتح البيع على النسخة النهائية.

تنفذ التجهيزات والاختبارات المستقلة دون انتظار هذه القرارات، وتُوثق العوائق في نوشن.
